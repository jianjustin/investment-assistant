## 1. 目标

1. 删除工作台用不到的 v1 遗留功能，连同代码、路由、页面、任务、配置段和数据表。
2. 遗留功能里仍有价值的三样东西并入工作台：K 线图、美股财季基本面、信号后超额统计。
3. 侧栏「更多」只剩共享底座的「工具」和「设置」。
4. 发布 `v2.1.0`。

成功标准：

- 仓库里（`docs/archive/`、`docs/specs/`、`docs/plans/` 中冻结的历史文档除外）不再有 Hermes、DeepSeek、SPY/VIX 市场信号、个股趋势快照、策略评分、事件研究、研究观察卡的代码路径、页面入口或使用说明。

- 离线测试、一次性库 SQL 测试、前端测试、前端构建全部通过。
- 真实库执行迁移 022 之后，工作台手动批处理成功，「今日」「标的」「复盘」「工具」「设置」页面正常。

## 5. 并入工作台

### 5.1 「标的」页 K 线图

- **后端**：`workbench/service.py` 的 `instrument()` 新增 `chart` 字段。从 `price_bars` 读当前修订、`cutoff_at=now`、截至 `session` 的最多 450 根日线，用新纯函数 `workbench/chart.py` 计算 MA20/50/200（简单均线，按收盘价），只返回最后 250 根：

  ```json
  "chart": {"bars": [{"price_date": "2026-10-23", "open": 0, "high": 0, "low": 0, "close": 0, "volume": 0,
                      "ma20": 0, "ma50": null, "ma200": null}],
            "adjustment": "split_only"}
  ```

  数据不足时对应均线为 `null`。原有的 `bars`（120 根，供时间线与最新日线文字）不变。
- **前端**：「标的」页顶部放图，复用 `lib/charts/CandleChart.svelte`、`lib/components/VolumeBars.svelte` 和 `lib/technicals.ts` 的 `toLineData`。图下注明「拆股调整、未分红调整」。`chart.bars` 为空时显示「暂无日线，等下一次批处理采集」。

### 5.2 「标的」页基本面一栏

- 计算口径、来源与哈希、只追加等规则沿用原有设计，见[归档 spec](../archive/roadmap-v1/specs/2026-10-16-cross-market-medium-term-research-design.md)。

### 5.3 上线前检查 `backcheck-2`

- 统计对象：`replay()` 已产出的 `signals`，即买入规则中能定价的触发（与成交、R 的统计同一批信号）。
- 每条信号、每个 h ∈ {5, 10, 20}：

  ```
  excess_h = close(ticker, t+h) / close(ticker, t) − close(SPY, t+h) / close(SPY, t)
  ```

  t 是信号日，t+h 是之后第 h 个交易日，都用 `replay` 读到的同一批当前修订日线。
- 第 h 个交易日在最后一根日线之后，计 `immature`；个股或 SPY 缺任一端点，计 `missing`。两者都不进入统计，也不用前值或未来值替代。
- 每条规则行和「合计」行新增：

  ```json
  "excess": {"5":  {"n": 0, "mean": null, "median": null, "positive_share": null, "immature": 0, "missing": 0},
             "10": {"...": "..."}, "20": {"...": "..."}}
  ```

  `positive_share` 是超额严格大于零的比例。`n = 0` 时三个统计量为 `null`。
- `CALC_VERSION = 'backcheck-2'`；`NOTE` 追加「超额是信号日收盘到第 h 日收盘，不代表可成交」。`flags`、阈值、`rule_backchecks` 表结构不变（新统计存在已有的结果 JSON 里）。
- 前端「复盘 → 上线前检查」表格新增 5/10/20 日超额列（n、均值、中位数、正超额占比）；`backcheck-1` 旧记录这几列显示「—」。
- 入口不变：`GET/POST /api/workbench/backchecks`、`python -m investment_assistant.workbench.backcheck [--tickers A,B]`。

### 5.4 SEC 文件记录移到「工具」

`routes/Data.svelte` 的 filings 标签原样抽成「工具」下的子页「SEC 文件」（筛选股票、类型、日期，下载原文）。接口 `/api/filings/records*` 不变。

## 10. 增补（2026-10-25）：推送路由与 `daily` 频道

> spec 审阅通过后，核对菜单时发现 §6 漏了推送路由，按用户决定以增补方式补入，正文不改。实施归入 plan 的 Task 9。

### 10.1 现状

- `NotifyConfig` 的默认路由（`config.py:63-70`）：`task_channels = {metrics: daily, filings: earnings, scores: signals, workbench: signals, workbench_review: signals}`，`task_enabled` 含同样五个键。
- `notify_settings` 表（008、012）里存的 `task_channels`、`task_enabled`、`webhooks` 会覆盖默认值（`services/settings.py` 的 `effective_notify_config`、`read_notify_view`），用户可以在「设置 → 推送配置」把任意任务改到任意频道。
- 删除 `metrics`、`scores` 之后，代码里没有任何默认路由指向 `daily`；但真实库存的路由是否指向 `daily` 未知。
- 遗留的通知模板：`notify/templates.py` 的 `metrics_summary`、`scores_summary`，`notify/notifier.py` 中对应的任务映射，`notify/discord.py` 测试 CLI 引用这两个模板。

### 10.2 决定

| # | 问题 | 决定 |
| --- | --- | --- |
| 10 | 推送路由里的 `metrics`、`scores` | 在 Task 9 一并删除：默认值去掉这两个键；读取已存设置时只保留仍会推送的任务（`filings`、`workbench`、`workbench_review`），库里残留的旧键不再显示、不再写回 |
| 11 | `daily` 频道 | 没有任何任务使用就一并去掉：`DiscordChannel.DAILY`、`DiscordClient` 的 `daily_url`、`DISCORD_WEBHOOK_DAILY`（环境变量页、健康检查的 webhook 计数、`from_env`/`from_config`）、测试 CLI 的 `--channel daily`、「设置 → 推送配置」的 `daily` 输入；读取已存的 `webhooks` 时只保留 `earnings`、`signals` |

### 10.3 「没有任何任务使用」的判定

- **代码侧**：删除后 `NotifyConfig` 默认路由里没有 `daily`，由测试断言。
- **真实库侧**：代码上线（重启 LaunchAgent）之前，经用户单独授权，只读执行

  ```sql
  SELECT task_channels, task_enabled, webhooks ? 'daily' AS has_daily_webhook FROM notify_settings;
  ```

  若 `filings`、`workbench`、`workbench_review` 中任一项的已存路由是 `daily`，**停下来问用户**：先在「设置 → 推送配置」把它改到 `signals` 或 `earnings`，再上线。`daily` 的 webhook 已配置但没有任务路由到它，不阻塞上线。
- **防御**：已存路由若仍指向已不存在的频道，`notifier` 返回 `{"sent": False, "reason": "unknown_channel: <name>"}`（推送结果照常写进运行报告），不抛异常、不拖垮任务。

### 10.4 不做

- 不新增迁移改写 `notify_settings`：它是配置不是业务数据，旧键在读取时过滤即可，迁移 022 的内容不变。
- 邮件渠道不受影响。
