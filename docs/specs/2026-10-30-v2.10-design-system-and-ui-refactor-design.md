# v2.10.0 设计标准与界面重构

> 2026-10-30，基线 `main@1940a7e`（`v2.8.0` 之后，v2.9 实施中）。路线见 [roadmap §4.8](../roadmap/roadmap.md#48-设计标准与界面重构v210)；用户 2026-10-30 提出「项目设计交互没有考虑，请根据项目特征选型 UI 框架或设计原语，roadmap 增加版本整理设计标准 + UI 重构」，插在 v2.9 之后（决策 #81–#86），原 v2.10 多数据源与降级顺延为 v2.11、原 v2.11 主动研究顺延为 v2.12。
> 本文回答三件事：**前端现在是什么状态**（§2，仓库核对的数字）；**选什么**（§3，框架与设计原语的选型及理由）；**标准是什么、怎么重构、怎么验收**（§4–§9）。实施 plan 开工前另写（`docs/plans/`）。§12 列出待你确认的问题；未确认前本文「先按」的选择就是默认值。

## 1. 目标

**要解决的问题**：前端自 v2.0 起由九个版本的功能需求逐页堆出来，没有一份设计标准。每个页面、每个组件各自决定颜色、按钮、表格、间距与空态文案；状态词（成功 / 降级 / 失败 / 跳过、入场期 / 持仓中 / 已结束、待审定 / 起草中……）各处用各自的颜色和写法；同一个「出错」在不同页面有五六种样子。用户的感受是「设计交互没有考虑」。随着 v2.9 把「今日」改成计划表、v2.12 再加研究档案页，不先立标准，新页面只会继续各写各的。

**本版完成后的状态**：

1. 仓库里有一份**设计标准**（活文档 `docs/design-system.md`，随代码更新），写清令牌、布局、状态词汇、数据块四态、组件清单、交互与文案规则；新页面照它搭，不再逐页定样式。
2. 前端有一层**设计原语**（`web/src/lib/ui/`）：通用组件（按钮、徽标、表格、对话框、页签、字段……）与领域组件（状态徽标、版本标、截止时间、样本量、涨跌数值、计划价位……），页面只组合它们。
3. 现有九个路由、四十个组件**全部迁到这层原语上**，功能、接口、文案与后端对齐的常量一字不改。
4. 有**静态守护**：不再出现原色类名（`text-red-600` 之类）、十六进制色值、emoji 图标、页面内自写样式；状态词都在一张映射表里。
5. 用户验收：任选三个页面，能说出「这个数字的口径 / 版本 / 样本量 / 截止时间在哪」「这一块为什么是空的（没算、无信号、失败、暂不可用）」；深浅色、窄屏都能读。

**不是本版目标**：加功能、改接口、改任何口径或文案常量；做品牌视觉设计；做移动端 App；换前端框架。

## 2. 现状核对（2026-10-30 仓库核对）

### 2.1 技术栈

| 层 | 现状 |
| --- | --- |
| 框架 | Svelte 5（runes、snippets），Vite 6，TypeScript 5.7，单页应用，hash 路由（`lib/router.ts`），无 SvelteKit、无 SSR |
| 样式 | Tailwind CSS 3.4（PostCSS 管线），`styles/tokens.css` 定义 15 个 CSS 变量（背景 / 表面 / 边框 / 文字 / 强调 / 成功 / 警告 / 危险 / 涨跌 / 两级阴影），`[data-theme='dark']` 深色，`tailwind.config.ts` 把变量映射成 `bg-bg`、`text-ink`、`text-muted`、`text-accent`、`text-success` / `warn` / `danger` 等类名 |
| 字体 | `@fontsource/inter`，`font-family: Inter, ui-sans-serif, system-ui`；**没有中文字体栈**（中文全靠系统回退），`.tabular` 工具类只在少数地方用 |
| 图标 | 侧栏与页头用 emoji（🗓️ 🔎 🧾 🗄️ 📚 🔧 ⚙️ 🔔 ⏾ ✕），`lucide` 在依赖里但**零引用**；折叠箭头是手写内联 SVG |
| 图表 | ECharts 5（`charts/EChart.svelte`）、lightweight-charts 4（`charts/CandleChart.svelte`） |
| 测试 | Vitest 4 + `@testing-library/svelte`，jsdom；`npm run build` 先跑 `svelte-check` |
| 规模 | `web/src` 共 12 844 行（含测试）；9 个路由文件、40 个组件、12 个 `lib/*.ts` 模块；最大的三个页面 `Review.svelte` 658 行、`Today.svelte` 557 行、`Instrument.svelte` 431 行 |

### 2.2 一致性核对

对 `web/src/**/*.svelte` 的 `class="…"` 字面量与标签做静态统计（Svelte 表达式里的类名未计，数字偏低）：

| 项 | 核对结果 | 说明 |
| --- | --- | --- |
| 语义色 vs 原色 | 错误文字用 `text-red-600` **54 处**、`text-danger` 11 处；警告用 `text-amber-700` **29 处**、`text-warn` 11 处 | 令牌存在但大多数地方没用，深色下 `red-600` / `amber-700` 不随主题变 |
| 十六进制色值 | `.svelte` / `.ts`（不含测试）里 **20 余处**：`CandleChart` 的标记与价位线颜色（`#0ea5e9`、`#a855f7`、`#f97316`、`#2563eb`、`#9333ea`……）、`Fundamentals` 的提示边框 `#d99b27`、ECharts 系列色 | 图表颜色不进令牌，深色下不变 |
| 按钮 | `<button class="…">` 字面量 **25 种**写法：描边按钮至少 6 种变体（`px-2 py-1` / `py-0.5`、带不带 `hover`、带不带 `disabled`）、实心按钮 5 种（`text-xs` / `text-sm` / 无字号、`px-2` / `px-3`）、**33 个 `<button>` 用 `underline` 伪装成链接** | 没有按钮组件；链接与按钮语义混用 |
| 表格 | 15 个文件里有 `<table>`，每张表各自写表头、对齐、字号与边框；数字没有统一右对齐与等宽数字 | 没有表格组件 |
| 圆角 | `rounded` 198 处、`rounded-lg` 5、`rounded-xl` 1、`rounded-md` 1、`rounded-full` 2；自写样式里另有 `5px` / `6px` / `7px` / `10px` | 实际用到 7 种圆角 |
| 页面内自写样式 | 7 个组件有 `<style>` 块（`Fundamentals`、`FinancialSeries`、`GuidanceEditor`、`MetricDetails`、`Watchlist`、`NodeGraph`、`Knowledge`），其中四个来自 v1 美股工作台，自带一套 `section` / `article` / `button` / `.primary` / `table` 样式，与 Tailwind 页面并存 | 两套视觉语言：v1 工作台（1.2rem 内边距、10px 圆角、1.1rem 标题）与 v2 页面（`p-3`、`rounded`、`text-lg`） |
| 响应式 | 全部 `.svelte` 里断点前缀只有 **7 处**（`md:grid-cols-*`、`sm:grid-cols-2`）；`NodeGraph` 自己用 `matchMedia('(max-width: 900px)')`；侧栏固定 `w-48`，抽屉固定 `w-96` | 手机上基本不可用（Discord 推送里的链接会在手机上打开） |
| 焦点与键盘 | `focus:` / `focus-visible:` 类 **0 处**；`Modal` 无焦点圈、无焦点陷阱、`Esc` 绑在遮罩 `div` 上（遮罩没有焦点时不触发）；`Drawer` 同 | 键盘不可用；`aria-*` 用了 36 个文件，基础尚可 |
| 状态词 | 运行节点 7 种、链状态 4–6 种、数据族三色、任务 4 种、复盘卡 4 种、知识版本……各自写在页面里；`StatusPill` 只认 8 个英文键，不认识的一律灰色并**原样显示英文键** | 没有状态词汇表 |
| 数据块空态 | 「暂无」「无持仓」「尚未复查」「样本不足」「暂不可用：<原因>」「迁移 027 未执行」各处各写；「没算」「无信号」「失败」三者在界面上没有统一的区分方式 | roadmap §2 原则 3「区分没算和无信号」在界面层没有落实手段 |

**结论**：令牌、Tailwind、深色、无障碍属性的底子都在，问题是**没有中间层**——令牌直接到页面，中间没有组件与规范，于是每页重新发明。要做的不是换框架，而是补这一层并把页面迁上去。

## 3. 选型

### 3.1 项目特征 → 对选型的要求

| 特征 | 要求 |
| --- | --- |
| **数据密集、以表为主**：15 张表、v2.9 起「今日」就是一张表、「标的」页计划历史表、运行详情三块明细 | 紧凑密度（默认行高 ≤ 32px）、数字右对齐与等宽数字、分组表头、行展开、粘性表头、已结束行置灰；不要营销站式的大留白 |
| **状态语义重**：运行 / 链 / 数据族 / 任务 / 卡 / 版本的状态词与颜色要全站一致，深浅色都成立 | 语义令牌（success / warn / danger / info / neutral / running）+ 一张状态映射表；不依赖某套 UI 库的内置颜色名 |
| **诚实优先于漂亮**（roadmap §2）：每个数字带口径 / 版本 / 样本量；区分没算、无信号、失败、降级 | 这些在任何通用 UI 库里都没有，必须自写**领域原语**；通用库只负责按钮、对话框这类无业务含义的部件 |
| **只追加版本、截止时间覆盖一切** | 版本标（第 k 版 / 最新第 n 版）、截止时间、`concept:` / `know:` 引用的统一呈现 |
| **中文界面** | 中文字体栈、中文标点、全角与半角间距、不依赖英文大小写做层级 |
| **单用户、本地、桌面为主，手机只读**：Discord 推送链接在手机打开「今日」「计划页」「运行详情」 | 桌面 ≥ 1024px 为主；三个只读路径在 375px 可读；其余页面窄屏横向滚动即可 |
| **Svelte 5 + Tailwind 已就位，代码主要由 Agent 实现**（CLAUDE.md） | 选 Agent 熟悉、文档完善、约定稳定的方案；组件代码**进仓库**（可读、可改、可测），不依赖运行时黑盒；组件用 role / 文本可查，现有 testing-library 测试照常 |
| **已有 ECharts 与 lightweight-charts** | 不换图表库，图表颜色改从令牌读 |
| **无 SvelteKit、hash 路由、Vite 单页** | 不引入要求 SvelteKit 的方案 |

### 3.2 候选

| 方案 | 做法 | 优点 | 问题 |
| --- | --- | --- | --- |
| **A 现状规范化**：继续 Tailwind 3，自写全部组件，不引任何 UI 依赖 | 新建 `lib/ui/`，按钮、表格等全部手写 | 零依赖、完全可控 | 对话框、弹出层、页签、下拉的无障碍（焦点陷阱、`aria-*`、键盘导航、滚动锁定）要自己实现并维护，正是现在缺的；Agent 容易再写出各自的版本 |
| **B 无样式原语 + 自写样式**：Bits UI（headless，Svelte 5 原生，snippets / runes）承担交互与无障碍，样式用现有令牌与 Tailwind 自写 | 引 `bits-ui`，每个通用组件在 `lib/ui/` 包一层 | 无障碍与键盘行为由库负责；视觉完全是自己的；代码在仓库里 | 每个组件的包装与样式仍要自写，初始工作量比 C 多；Bits UI 以 Svelte 5 重写过一次，API 以当前主版本为准 |
| **C 复制进仓库的组件集**：shadcn-svelte（基于 Bits UI + Tailwind，CLI 把组件源码复制进 `lib/ui/`，之后由仓库维护） | `npx shadcn-svelte init`，逐个 `add` 需要的组件，再按本文令牌改样式 | 一步得到按钮、徽标、表格、对话框、抽屉、页签、下拉、工具提示、折叠、提示条等约 15 个组件的成熟实现；令牌命名（`--background` / `--foreground` / `--primary` / `--muted` / `--border` / `--destructive` / `--ring`）与深色方案是业界通用约定，Agent 最熟悉；代码进仓库，无运行时依赖黑盒 | 当前版本**要求 Tailwind v4**（Tailwind 3 项目需先升级）；默认视觉偏「中性灰 + 大圆角」，要按本文令牌改；CLI 默认以 SvelteKit 的 `$lib` 别名生成路径，Vite 单页要配 `components.json` 的别名 |
| **D 主题化组件库**：Skeleton v3（Tailwind v4 + Zag.js） | 装两个包，用它的主题系统 | 组件齐、带主题生成器 | 自带一整套设计意见（色阶、字号、圆角、「preset」类名），与现有令牌与页面风格相冲；组件源码在 `node_modules`，改不动；对 Agent 而言约定不如 C 通用 |
| **E Flowbite Svelte / 其他 Tailwind 主题库** | 同 D | 组件数量多 | 同 D；视觉更偏营销站与后台模板，与数据密集型工作台不合 |
| **F 企业数据组件库**：Carbon Design System（`carbon-components-svelte`） | 整套换 Carbon | 为数据密集场景设计，表格与状态组件成熟 | 自带完整视觉系统与 CSS，与 Tailwind 并存要两套样式体系；Svelte 5 支持状态需核实；对单用户本地工具过重；不利于保留现有 Tailwind 页面逐步迁移 |

### 3.3 决定（先按；§12 Q2、Q3 待确认）

**选 C（shadcn-svelte 复制进仓库）作通用层，自写领域层；随之把 Tailwind 升到 v4，令牌改为 CSS-first；图标用 `@lucide/svelte`；图表库不换。** 具体：

| 层 | 选择 | 理由 |
| --- | --- | --- |
| 样式引擎 | **Tailwind CSS v4**（`@tailwindcss/vite` 插件，`@import "tailwindcss"` + `@theme`），用官方 `@tailwindcss/upgrade` 迁移现有类名 | C 的前提；v4 的 `@theme` 把令牌定义搬进 CSS，正好把现有 `tokens.css` 与 `tailwind.config.ts` 两处合成一处；Node 26 满足要求 |
| 交互原语 | **Bits UI**（随 shadcn-svelte 引入） | 对话框焦点陷阱、`Esc`、滚动锁定、页签与下拉的键盘导航、`aria-*`，全部由它负责；现有 `Modal` / `Drawer` / `ConceptTerm` 的弹出层问题（§2.2）一并解决 |
| 通用组件 | **shadcn-svelte** 复制进 `web/src/lib/ui/`：`Button`、`Badge`、`Table`、`Dialog`（含确认框）、`Sheet`（替代 `Drawer`）、`Tabs`、`Select`、`Input` / `Textarea` / `Label`、`Tooltip`、`Popover`（`ConceptTerm` 用）、`Collapsible`、`Alert`、`Skeleton`、`Separator`、`Toast`（`svelte-sonner`，shadcn-svelte 默认）；**不**加 `Card` 以外的营销类组件（`Carousel`、`Hero` 之类） | 一次拿到成熟实现与统一约定；源码在仓库，按本文令牌改样式后即为项目自己的组件；Agent 对其 API 与类名最熟 |
| 领域组件 | **自写**，放 `web/src/lib/ui/domain/`（§4.6） | 任何库都没有「状态徽标映射表」「版本标」「截止时间」「样本量」「涨跌数值」「计划价位」 |
| 令牌命名 | 采用 shadcn 的语义名（`--background`、`--foreground`、`--card`、`--muted`、`--muted-foreground`、`--primary`、`--border`、`--ring`、`--destructive`），现有 `--bg` / `--surface` / `--text` / `--text-muted` / `--accent` / `--danger` 一一映射并删除；**保留并扩展**项目自己的语义色：`--success` / `--warn` / `--info` / `--running`（状态）与 `--up` / `--down`（涨跌），以及图表角色色 `--chart-rule` / `--chart-own` / `--chart-agent` / `--chart-fill` | 通用约定给通用层，项目语义给领域层，两者不混 |
| 图标 | **`@lucide/svelte`**（Svelte 5 专用包，按图标路径引入、可摇树），删除未用的 `lucide` 包与全部 emoji | 已在依赖里选过 lucide，只是没接上 |
| 字体 | Inter 保留给拉丁与数字，中文字体栈 `"PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif`；数字一律 `font-variant-numeric: tabular-nums` | 中文不再靠浏览器默认回退；表格数字对齐 |
| 图表 | ECharts、lightweight-charts 保留；新增 `lib/charts/theme.ts` 在运行时读 CSS 变量生成 ECharts 主题与 K 线配色，主题切换时重绘 | 图表颜色随令牌与深浅色变，删掉组件里的十六进制 |

**不选 A** 因为无障碍与弹出层行为自写成本高、且已被证明会漂移；**不选 D / E / F** 因为它们自带视觉意见与运行时样式，与「组件源码在仓库、按项目令牌改」的要求相反。**B 是 C 的降级方案**：若用户不接受升 Tailwind v4（Q2），退回 B：留 Tailwind 3，直接装 Bits UI，通用组件按 shadcn-svelte 的源码手工移植、类名按 Tailwind 3 写。两者的领域层、标准与守护完全相同，只有通用层的来路不同。

**版本锁定**：shadcn-svelte、Bits UI、`@lucide/svelte`、Tailwind v4、`@tailwindcss/vite`、`svelte-sonner` 的具体版本在写 plan 时按 npm 当时的稳定版锁进 `package.json`（精确版本，不用 `^`），本文不写版本号。

## 4. 设计标准 v1

本节是标准的首版，开工时原样落成活文档 `docs/design-system.md`（之后随代码更新，本 spec 冻结）。

### 4.1 原则

1. **先把状态说清，再谈好看。** 每个数据块必须能表达五态之一：加载中 / 无数据 / 没算 / 降级 / 失败（§4.5）；没有「看起来正常但其实是空」的状态。
2. **数字可追溯。** 任何统计数字旁边或所在块的页头，能看到口径版本（`calc_version` 之类）、样本量、截止时间或数据时点中的相关项；没有样本量不给均值（沿用 v2.7 规则）。
3. **密度优先。** 这是一个每天读几分钟的工作台，不是落地页：默认紧凑密度，一屏尽量多放信息，用层级而不是留白分隔。
4. **一致胜于新颖。** 同一含义全站一个写法、一个颜色、一个组件；新需求先查标准，标准没有再加组件并更新标准。
5. **可读的中文。** 中文字体栈、中文标点、「」引号、数字与单位之间半角空格、时间标注时区（沿用 `fmtBeijing`）。

### 4.2 令牌

| 组 | 令牌 | 规则 |
| --- | --- | --- |
| 表面 | `--background`、`--card`、`--muted`、`--border`、`--ring` | 页面底、卡片 / 表面、次级表面、边框、焦点圈；只这五个层次 |
| 文字 | `--foreground`、`--muted-foreground` | 正文与次要文字两级；不再有第三种灰 |
| 强调 | `--primary` / `--primary-foreground` | 唯一的强调色（现 `#0f766e` 青绿），用于主按钮、当前导航、链接 |
| 状态 | `--success`、`--warn`、`--destructive`、`--info`、`--running`、`--neutral` 各带 `-foreground` | 对应状态语气 §4.4；**页面里不得出现原色类名**（`red-600`、`amber-700`、`sky-500`……） |
| 涨跌 | `--up`、`--down` | 美股约定绿涨红跌（现状；§12 Q5 可改为红涨绿跌），只用于价格 / 收益数值，不用于状态 |
| 图表 | `--chart-rule`、`--chart-own`、`--chart-agent`、`--chart-fill`、`--chart-grid` | 规则 / 自定 / Agent 三种来源各一色（K 线价位线、推导、对比图共用），其余序列用 `--chart-1…5` |
| 字号 | `text-xs` 12 / `text-sm` 13 / `text-base` 14 / `text-lg` 16 / `text-xl` 20，仅五档 | 页面正文 `text-sm`，表格 `text-xs` 或 `text-sm`，页面标题 `text-lg`，不再用 `text-2xl` 以上 |
| 间距 | Tailwind 4px 基数，组件内 `1 / 2 / 3`，块间 `4 / 6`，页内分段 `8` | 不用 `.65rem`、`1.2rem` 这类自写值 |
| 圆角 | `--radius` 一个值（6px），`rounded-full` 只给徽标与头像 | 删掉其余五种 |
| 阴影 | `--shadow-1`（表面）、`--shadow-2`（浮层）两级 | 沿用现 `--elev-1` / `--elev-2` |
| 动效 | 过渡 150ms，仅颜色与透明度；运行中状态用边框脉冲（沿用 `NodeGraph`）；不做进场动画 | `prefers-reduced-motion` 时全部关闭 |
| 深浅色 | `[data-theme]` 两套令牌值；首次打开跟随系统（`prefers-color-scheme`），用户切换后记本地（§12 Q6） | 两套都要满足 WCAG AA 对比（正文 4.5:1、次要文字 3:1）；每个状态色都在两套里各调一次 |

### 4.3 布局

- **应用壳**：左侧栏（可折叠，折叠后只剩图标 + 工具提示）、顶栏（当前页标题、事件提示、主题切换）、内容区 `max-w-[1400px]`，表格页允许撑满。侧栏与顶栏是 `AppShell` 唯一的职责。
- **页头**（每个路由与每个大段落一致）：标题 + 口径 / 时点 / 版本的一行次要文字 + 右侧动作区（**至多一个主按钮**，其余描边或链接）。
- **分段**：`Section`（标题 + 可选说明 + 内容），不嵌套超过两层；卡片只给「一个对象」（一份计划、一张复盘卡、一个数据族），列表性内容用表格不用卡片堆。
- **网格**：桌面 ≥ 1024px 两栏或四栏；768–1023 两栏；< 768 单栏。
- **窄屏（< 768px）**：「今日」计划表、计划页 `#plan/<id>`、运行详情 `#tools/runs/<id>` 三个只读路径以**行转卡**呈现（每行变一张紧凑卡，字段名在左）；其余页面表格横向滚动、侧栏变顶部抽屉。不做 < 375px。

### 4.4 状态词汇与语气

全站状态词统一进 `web/src/lib/ui/domain/status.ts` 一张表：`{ 领域, 键, 中文, 语气 }`，`StatusPill` 只认这张表，**不认识的键在开发模式抛错、在生产显示中性灰加原键**（测试 `test_status_vocabulary` 守护：后端能产生的每个状态键都在表里）。

| 语气 | 令牌 | 用于 |
| --- | --- | --- |
| `success` | `--success` | 成功、已完成、已审定、已连接、`green`、`done`、`active` |
| `warn` | `--warn` | 降级、部分成功、待审定、起草中、`yellow`、`pending`、`gate_hold`、样本不足 |
| `danger` | `--destructive` | 失败、起草失败、作废、`red`、`error`、需要重新登录 |
| `info` | `--info` | 入场期、修订版、新版本、提示类说明 |
| `running` | `--running` | 运行中、复查中、登录中、轮询中（带脉冲） |
| `neutral` | `--neutral` | 跳过、未开始、已结束、过期、被取代、已平仓、只手动、旧版本运行 |

领域覆盖（首版）：运行节点 7 态；链状态（入场期 / 持仓中 / 退出期 / 已结束及其子类）；数据族三色；任务状态；复盘卡 4 态；知识条目（现行 / 已归档 / 草稿）；Agent 连接；推送结果；执行状态（v2.9 `execution-1`）。颜色只表达语气，**文字必须同时出现**（不只靠颜色）。

### 4.5 数据块五态

每个取数的块（页面、段、卡、表）用同一个 `DataBlock` 包装，必选 `state`：

| 态 | 显示 | 文案规则 |
| --- | --- | --- |
| `loading` | `Skeleton`，形状接近最终内容 | 不写字 |
| `empty` | 一行次要文字 | 写**为什么空**：「无持仓」「今日无触发」「暂无成交」——是业务上的「无信号」 |
| `not_computed` | 一行次要文字 + `warn` 徽标「没算」 | 写**缺什么**：「缺资金快照，未计算股数」「样本 3 个，少于 5 个不给均值」——与 `empty` 严格区分（roadmap §2 原则 3） |
| `degraded` | 内容照常显示 + 顶部 `Alert`（warn） | 写**哪部分不全**与原因：「Yahoo 空结果，日线用上一交易日」「概念卡暂不可用：<原因>」 |
| `error` | `Alert`（danger）+ 重试按钮（若可重试） | 原因来自接口 `{"error": "<代码>"}` 的中文映射（沿用各 `*_TEXT` 表），不显示原始英文码与堆栈 |

页面级错误（整页取不到）用同一组件撑满内容区；块级错误只占该块。**禁止**用空白、`—`、`null`、`undefined` 表达以上任一态。

### 4.7 交互规范

- **动作**：一个页头或一段至多一个 `primary` 按钮；不可逆动作（续跑、重新运行 Agent、作废成交、断开连接、归档知识、撤回补充）必须经 `ConfirmDialog`，确认按钮写动作名不写「确定」。
- **提交与幂等**（沿用 `request_id` 规则）：提交中按钮 `busy`、表单只读；失败保留草稿与 `request_id` 并在表单内 `Alert` 显示原因；成功后 `Toast`。
- **轮询**（重新复查、讨论回答、登录、续跑）：进行中显示 `running` 徽标与已等待时间；超时文案沿用各自的 `*_PENDING_TEXT`，不自动无限重试。
- **链接与按钮**：导航用 `<a href="#…">`（可中键打开、可复制），动作用 `<button>`；二者视觉不同（链接下划线，按钮无下划线）。
- **键盘**：所有可交互元素 `focus-visible` 显示 `--ring` 焦点圈；`Esc` 关闭最上层浮层；表格行展开可用 `Enter`；侧栏可 `Tab` 遍历。
- **表单**：标签在上；错误在字段下且 `aria-describedby`；数字字段 `inputmode="decimal"`、右对齐；日期时间字段注明时区。
- **表格**：数字列右对齐等宽；文本列左对齐；状态列用 `StatusPill`；表头可带工具提示；超过 50 行的表分页或「显示更多」（接口已有 `total`）；已结束 / 作废 / 被取代的行置灰（`muted`），不删不隐藏。
- **深浅色**：切换即时生效（图表重绘），所有颜色经令牌。
- **安全**：不新增 `{@html}`（现状只在知识卡页），迁移时不得为了样式引入。
- **文案**：错误原因一律中文映射，不显示英文码；相对时间只作工具提示，正文写绝对时间。

### 4.8 图标与图表

- 图标只用 `@lucide/svelte`，通过 `Icon` 组件；导航图标：今日 `calendar-days`、标的 `search`、复盘 `clipboard-list`、数据 `database`、知识 `book-open`、工具 `wrench`、设置 `settings`、运行 `activity`、通知 `bell`、主题 `sun-moon`。不再出现 emoji（守护 §6）。
- ECharts：`lib/charts/theme.ts` 在挂载与主题切换时读取 `--foreground`、`--muted-foreground`、`--border`、`--chart-*` 生成主题对象并 `setOption`；系列色按来源角色（规则 / 自定 / Agent）而不是序号。
- K 线：涨跌用 `--up` / `--down`；标记与价位线按 `--chart-rule` / `--chart-own` / `--chart-agent`；作废计划用 `--chart-fill` 淡显；删掉全部十六进制。
- 图表旁必有文字说明口径与时点（`CalcVersion` + `CutoffTime`）。

### 4.9 文案

沿用现状并写进标准：全角标点，「」作引号，中西文与数字之间半角空格，单位紧跟数字（`12 股`、`-3.2%`），时间 `fmtBeijing` 并标注「北京时间」，版本 `第 k 版`，口径名用等宽字体（`CodeText`）。与后端逐字对齐的文案常量（`AGENT_REASON_TEXT`、`RESUME_ERROR_TEXT`、`conditionText`、`EXECUTION_TEXT` 等）**一字不改**，仍由现有跨语言测试守护。

- 波 4：`cd web && npm test && npm run build`；离线全量 pytest（`env -u INVESTMENT_ASSISTANT_DATABASE_URL -u INVESTMENT_ASSISTANT_TEST_DATABASE_URL -u TEST_DATABASE_URL .venv/bin/python -m pytest tests/ -q`）；一次性库全量不需要（无 SQL 改动），但跨语言同步测试属于离线集，必须通过。
- 现有全部前端测试在不改断言文本的前提下通过（文案不变是硬约束；因组件结构变化需要改的只能是选择器，不是期望文本）。

### 8.2 手动验收（你做，记录进 `v2.10-acceptance.md`）

1. 打开 `#_ui` 画廊：每个组件在浅色、深色下各看一遍，没有一处颜色不随主题变；每个状态语气能从文字读出，不只靠颜色。
2. 「今日」「标的」「复盘」任选三个统计块，说出口径、样本量、时点各在哪。
3. 找到至少三个不同的「空」：一个是无信号（`empty`）、一个是没算（`not_computed`）、一个是失败或暂不可用（`error` / `degraded`），三者在界面上一眼可分。
4. 用键盘走完一次：`Tab` 到「从此节点继续」或「断开」→ `Enter` 打开确认框 → `Esc` 关闭 → 焦点回到按钮。
5. 手机（或浏览器 375px）打开推送里的「今日」、计划页、运行详情，能读、能展开行、不横向滚动。
6. 侧栏折叠后悬停图标能看到标签；全站没有 emoji。
7. 你确认：连续一周使用后，没有「这块为什么这样」的新疑问来自样式或状态表达不一致（有则记为本版待修项）。

## 9. 风险

| 风险 | 处理 |
| --- | --- |
| Tailwind v4 升级改坏类名或断点（codemod 处理不到 Svelte 表达式里拼出来的类名，如 `{active ? 'bg-accent/10' : …}`） | 升级后先跑全部前端测试与 `svelte-check`；用画廊逐组件目检；表达式里的类名在波 1–3 迁移时逐个经手 |
| shadcn-svelte 复制进来的代码量大、带默认视觉 | 只 `add` §4.6 列出的组件；改样式时删掉不用的变体；守护对 `lib/ui/` 同样生效 |
| 令牌改名波及所有页面 | 波 0 先保留旧名作别名（`--bg: var(--background)` 等），波 4 删别名；守护在波 4 才阻断 |
| 没有视觉回归测试，重构可能悄悄改坏布局 | 不引 Playwright（§10）；用画廊 + 每波验收截图（浅 / 深各一张存 `docs/roadmap/v2.10-acceptance/`）人工比对；功能行为由现有测试守 |
| 与 v2.9 前端并行改同一批文件 | §5 的顺序约束：codemod 与波 1 等 v2.9 前端合入；plan 里写明文件归属 |
| Bits UI / shadcn-svelte 的 API 随主版本变 | 版本精确锁定；组件源码在仓库，升级是可选项不是被动项 |
| 中文字体栈在 Linux / Windows 上效果不同 | 只保证 macOS（运行机）与 iOS Safari（手机只读）；其他平台回退到 `sans-serif` |

## 10. 不做 / 已知限制

- 不加功能、不改接口、不改口径、不改任何与后端对齐的文案常量。
- 不换框架（不迁 SvelteKit、不上 SSR）、不改 hash 路由。
- 不做品牌 / 视觉形象设计（名字「Hermes」、favicon、强调色沿用；§12 Q7）。
- 不做 Playwright / 截图回归、不做 Storybook（画廊路由替代）。
- 不做国际化、不做 < 375px、不做桌面以外的交互优化（手机只读三条路径）。
- 不改 Discord 推送的文本格式。
- 已知限制：`{@html}` 的知识卡页样式由后端渲染的 HTML 决定，只能在容器层套令牌；ECharts 的工具提示浮层样式需单独映射令牌；lightweight-charts 的字体与网格色只能在实例化时设置，切主题需重建实例。
