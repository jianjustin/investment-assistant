# P2 观察池扩展与市场环境 — 设计

日期：2026-10-23。基线 `main@4aec0da`。本文是设计，不是实施计划；实施计划另写。
上位文档：[roadmap v2](../roadmap/v2-decision-loop.md) 的 P2。在 [P1 设计](2026-10-23-p1-rule-plans-and-push-design.md) 之上扩展，P1 未改动的部分继续有效。

## 1. 目标与非目标

把工作台的标的范围从 10 只扩到 100 只并分成核心池和扩展池；给每份计划加上市场环境（区制、行业强弱、信用利差与期限利差）和下次财报日；新增一个只在上线新规则前手动运行的历史检查。

已确认的前提（2026-10-23）：

| # | 决策 | 结论 |
|---|---|---|
| 1 | 分层存在哪里 | 数据库观察名单 `watchlist_items`：`active` 的美股即观察池，标签 `core` 即核心池；在「设置 → 观察名单」维护 |
| 2 | 区制标签 | 只由池内广度决定，只作提示，不改价位、仓位和有效性；HY 利差、2s10s 只作背景数值 |
| 3 | 扩展池单元 | 生成规则计划并影子跟踪；不调用 Codex、不进「今日」待决定列表、不推送 |
| 4 | FRED 接入 | 官方 API，密钥取环境变量 `FRED_API_KEY`；未配置时运行报告写「未配置」，不写库 |

本文另定的默认值（审阅时可改）：行业映射用观察名单标签 `sector:<ETF>`；历史检查只读已存 K 线，不补采；批处理耗时预算 30 分钟；采集保持串行，不加并发。

非目标：不新增交易规则；不改计划公式（仍为 `plan-1`）；不引入 Agent（P3）；不推送周度与月度复盘（P4）；不补采更长历史；不改 Codex 解读的输入与提示词；不改写或回填旧表数据。Phase 0 正式 Gate 仍为 HOLD。

## 2. 设计原则

沿用工作台与 P1 原则：只追加；按时点可还原；版本照记；失败不冒充空。P2 特别强调：

1. **分层可还原。** 观察名单表是可变的，所以批处理把每次看到的分层追加进 `pool_tiers`；复盘按信号日当时的分层归池，不按现在的。
2. **环境只提示。** 区制、行业强弱和利差写进计划的 `inputs.context` 与 `warnings`，不参与价位与仓位计算，所以不升 `plan_version`。
3. **每个数据源单独报告。** 日线、资讯、财报日期、SEC、ETF、FRED、区制各自记录成功与失败，运行报告能看出是哪一个坏了。

## 3. 数据模型

迁移 `018_pool_and_market_context.sql`，只新增四张表，不改旧表。时间戳为 `TIMESTAMPTZ`，由服务端生成。

### 3.1 `pool_tiers` — 分层变更记录

`id`、`ticker`、`tier`（`core` / `extended` / `removed`）、`sector_etf`（可空）、`effective_session`（DATE）、`recorded_at`。

某股的 `(tier, sector_etf)` 与它最新一行不同时才追加。某股在某日的分层 = `effective_session <= 该日` 且 `recorded_at <= 截止时间` 的最新一行；没有记录为「未知」。

### 3.2 `macro_observations` — FRED 观测值

`id`、`series_id`、`obs_date`、`value`、`fetched_at`、`created_at`。`(series_id, obs_date)` 首次出现或数值与该日期最新一行不同时追加（修订）。按时点读取：`fetched_at <= 截止时间` 的每个日期的最新一行。

### 3.3 `market_regimes` — 每日市场环境快照

`id`、`session`、`calc_version`（`regime-1`）、`label`（`risk_on` / `neutral` / `risk_off` / `insufficient`）、`breadth`、`sectors`、`macro`、`inputs`（JSONB）、`created_at`。`(session, calc_version)` 唯一；重跑结果相同返回已有行，不同则记入运行报告的冲突列表，不覆盖。

### 3.4 `rule_backchecks` — 历史检查结果

`id`、`calc_version`（`backcheck-1`）、`params`、`stats`（JSONB，生成时冻结）、`created_at`。

计划的环境信息放在 `trade_plans.inputs.context`（已有 JSONB 列），不改表。

## 4. 观察池

### 4.1 来源与上限

| 项 | 规则 |
|---|---|
| 观察池 | `watchlist_items` 中 `status = 'active'` 的美股（A 股条目忽略） |
| 核心池 | 观察池中带标签 `core` 的（大小写不敏感） |
| 扩展池 | 观察池中其余的 |
| 行业映射 | 标签 `sector:<ETF>`，`<ETF>` 取 `SMH`、`XLK`、`QQQ` 之一（大小写不敏感）；没有该标签即「未映射」 |
| 上限 | 观察池 ≤ 100 只，核心池 ≤ 15 只 |

上限和标签在两处检查：观察名单写入时（超限、未知 ETF、多个 `sector:` 标签 → 400）；批处理开始时（超限 → 批处理失败并写明原因，不静默截断）。核心池为空不算失败：批处理照跑，运行报告记 `core_empty`，推送概览写「核心池为空，只推送持仓」。

### 4.2 批处理范围与分层同步

批处理标的 = 观察池 ∪ 当前持仓。持仓股不论分层都按核心池对待（推送、解读），但不在观察池中的持仓不计入广度。

批处理开始时，把当前分层与 `pool_tiers` 中各股的最新状态比较，变化的追加一行，`effective_session` = 本次交易日；从观察池中移除的写 `removed`。

### 4.3 单元归属

信号日的分层为 `extended` 且当前无持仓的单元归扩展池，其余（核心、未知、持仓）归主列表。P2 之前的单元没有分层记录，按主列表处理；P1 的计划全部推送过，复盘时按核心池计。

扩展池单元：生成 `rule` 计划（仓位照算）、影子跟踪；不调用 Codex；不计入待决定数；不推送；在「今日」只读折叠显示。

## 5. 市场环境

### 5.1 数据

| 数据 | 采集 |
|---|---|
| 行业 ETF 日线 | `SMH`、`XLK`、`QQQ` 与 `SPY` 一样每次批处理采集日线，存 `price_bars`；不采资讯和财报日期 |
| FRED | `BAMLH0A0HYM2`（美国高收益债 OAS）、`T10Y2Y`（10 年减 2 年国债利差）；每次取交易日前 120 天；值为 `.` 的观测跳过；未配置密钥时不发请求，状态 `not_configured` |

FRED 密钥只从环境变量读取，不写入日志、运行报告或错误信息（异常文本中出现时替换为 `***`）。

### 5.2 池内广度与区制（`regime-1`）

范围：观察池中当日有 K 线的股票，用 `adj_close`。

| 指标 | 合格样本 | 判定 |
|---|---|---|
| 站上 MA50 | ≥ 50 根 K 线 | `adj_close > MA50` |
| 站上 MA200 | ≥ 200 根 | `adj_close > MA200` |
| 52 周新高 / 新低 | ≥ 252 根 | `adj_close` ≥ 前 251 根最高 / ≤ 前 251 根最低 |

占比 = 满足数 ÷ 合格样本数。标签：

| 标签 | 中文 | 条件（按顺序判断） |
|---|---|---|
| `insufficient` | 样本不足 | MA200 合格样本 < 20 |
| `risk_on` | 进攻 | MA200 占比 ≥ 60% 且 MA50 占比 ≥ 50% |
| `risk_off` | 防守 | MA200 占比 < 40% 且 MA50 占比 < 30% |
| `neutral` | 中性 | 其余 |

阈值为先验设定，不拟合；改阈值即发新 `calc_version`。

### 5.3 行业相对强度

`rs20`、`rs60` = ETF 近 20 / 60 个交易日的 `adj_close` 收益 − 同期 SPY 收益。两者都 < 0 为 `weak`，都 > 0 为 `strong`，其余 `mixed`；K 线不足为空。

### 5.4 利差背景

每个序列给截至交易日的最新值、日期，以及与 20 个观测之前相比的变化。只显示，不参与任何判定。

### 5.5 快照

区制、行业强弱、利差在采集之后、规则之前算一次，写入 `market_regimes`。计算失败时运行报告记错误，当日计划的区制为空并提示 `regime_unavailable`。

## 6. 计划的环境信息

`rule` 与 `own` 计划生成时冻结 `inputs.context`：

| 键 | 内容 |
|---|---|
| `context_version` | `context-1` |
| `pool_tier` | 信号日的分层（`core` / `extended` / `unknown`） |
| `regime` | `{id, label}`，失败时为空 |
| `sector` | `{etf, rs20, rs60, state}`，未映射时为空 |
| `next_earnings` | 下次财报日；未知为空 |

新增提示：`regime_risk_off`（区制为防守）、`regime_unavailable`（快照失败）、`sector_weak`（映射的 ETF 为 `weak`）。价位、仓位、状态的计算与 `store_plan` 的比较不变。

## 7. 批处理

### 7.1 顺序

1. 读取观察池并同步分层（新增）。
2. 采集：SPY 与行业 ETF 日线（新增 ETF）；每只股票日线、资讯、财报日期；SEC；FRED（新增）。
3. 市场环境快照（新增）。
4. 规则、合成单元、生成计划（带环境信息）；只为主列表单元生成 Codex 解读。
5. 推送（定时运行）。

### 7.2 运行报告新增

| 键 | 内容 |
|---|---|
| `pool` | 核心数、扩展数、持仓数、本次分层变更 |
| `etfs` | 每个 ETF 的日线写入结果或错误 |
| `macro` | 每个序列的写入结果、`not_configured` 或错误 |
| `regime` | 快照状态（`inserted` / `existing` / `conflict` / 错误）与标签 |
| `sources` | 按数据源列出失败：`bars`、`news`、`earnings`、`sec`、`etf_bars`、`fred`、`regime` |
| `timings` | 各阶段与总耗时（秒） |

总耗时超过 1800 秒时在 `errors` 记 `batch_over_budget`。「按时完成」指北京时间 06:30 开始的定时运行在 07:00 前完成并推送。

## 8. 今日与推送

- **今日**：`units` 只含主列表单元；新增 `extended_units`（只读：标的、信号日、动作、规则、计划价位与状态）与 `market`（最新环境快照）。
- **推送**：概览增加「市场环境」字段：区制与广度数值、三只 ETF 的 `rs20` 与强弱、HY OAS 与 2s10s 及其 20 个观测变化（未配置时写「FRED 未配置」），以及「扩展池新计划 N 份（不推送）」。新计划段只含主列表单元，每份增加「区制 · 下次财报日（或未知）· 行业强弱（或未映射）」。异常段按数据源分组。

## 9. 周度复盘（`review-3`）

新增「分池」视角：核心池与扩展池分开，每条买入规则给出当周触发次数、计划数、过期数、有成交的计划数、R 的均值与中位数。归池只看信号日的分层，不看持仓：计划取冻结的 `inputs.context.pool_tier`，没有时查 `pool_tiers`；`extended` 归扩展池，其余（含未知、P1 计划）归核心池。已生成的快照不变。

## 10. 历史检查（`backcheck-1`）

新规则上线前手动运行的检查，回答「触发是否过频、止损是否总被扫掉」。不调参数，不宣称有效。

| 项 | 规则 |
|---|---|
| 入口 | 「复盘 → 上线前检查」页签、`POST /api/workbench/backchecks`、命令行 `python -m investment_assistant.workbench.backcheck` |
| 范围 | 默认当前观察池，可指定标的 |
| 数据 | 只读库里已存的 K 线（当前修订）与 SEC 文件，不联网、不补采 |
| 预热区 | 每只股票前 200 根 K 线只用于指标预热，不产生信号；结果写明预热区与评估区起止 |
| 重放 | 评估区每个交易日以当时为止的 K 线运行现有规则（无持仓）；买入候选按 `plan-1` 算价位，用 `plan-shadow-1` 模拟 |
| 未成熟 | `valid_until` 之后不足 20 个交易日的信号计入触发数，不计入结果 |
| 统计 | 每条规则与合计：触发数、评估区股票日数、每 100 个股票日触发数、单股最多触发数、同日 ≥ 3 只同时触发的日数、成交数、过期数、成交后 5 个交易日内止损的占比、到达 T1 占比、R 的个数 / 均值 / 中位数 / 四分位 |
| 标记 | `too_frequent`：每 100 个股票日触发 > 5；`stops_swept`：成交 ≥ 10 且 5 日内止损占比 ≥ 50%；`insufficient`：成交 < 10 |

结果冻结进 `rule_backchecks`，页面注明「描述性检查，不调参，不代表规则有效」。

## 12. 测试与交付

- **纯函数**：分层解析与上限、标签大小写与重复；广度合格样本与四种标签边界；行业强弱三态与数据不足；利差变化；环境信息与新提示；历史检查的预热区、未成熟、标记阈值。
- **数据库**：一次性 PostgreSQL（端口 55433）执行迁移 018；分层只在变化时追加、按时点读取；FRED 修订追加与按时点读取；区制快照唯一与冲突。
- **批处理**：100 只替身数据跑通并记录各阶段耗时；单个数据源失败只影响自己并在 `sources` 中区分；扩展池不调用 Codex；FRED 未配置。
- **推送**：市场环境字段、扩展池计数、按数据源分组的异常，仍满足 Discord 限制。
- **前端**：vitest 覆盖观察名单的核心与行业控件、今日的市场环境与扩展池、复盘的分池与上线前检查。
- **文档（DoD）**：更新 `docs/us-workbench.md`，写明手动入口、验证入口与验证示例。

真实库执行迁移 018、在观察名单中标记核心池、配置 `FRED_API_KEY`、扩大观察池均单独确认；执行迁移前 `pg_dump` 备份。

## 13. 与现有能力的关系

| 现有能力 | 处理 |
|---|---|
| 配置 `watchlist` | 工作台不再读取；其他任务（如 `filings`）照旧 |
| `watchlist_items` 与观察名单页面 | 成为工作台观察池的来源；写入增加校验 |
| `rules.py`、`synthesis.py`、`briefs.py` | 不变；解读只对主列表单元调用 |
| `plans.py` | 新增环境信息与三个提示；公式与 `plan-1` 不变 |
| `plan_shadow.py` | 不变；历史检查复用 |
| `review.py` | 新增分池视角，`calc_version` 升为 `review-3` |
| `digest.py` / `templates.py` | 新增市场环境、扩展池计数、按数据源分组的异常 |
| `market_signals.market_status` | 不变，仍随单元显示；与新区制并存，不合并 |
| `MacroConfig.fred_series` | 不变；工作台用自己的两个序列 |
