## 是什么
推送是每日工作流的 `push` 节点（第九个，在复盘 `retro` 之前）：把当天的结果压缩成几条 Discord 消息，让你早上不用打开页面也知道有什么要处理。

## 怎么算 / 从哪来
- **顺序**：概览（含市场环境、扩展池新计划数、计划更新数、复盘卡行、数据降级行）、新计划、计划更新（有更新时才发）、持仓、待处理与异常、筛选报告。平常五条，有计划更新时六条。
- **范围**：核心池、持仓股和可决定的筛选单元；扩展池不推送（见[观察池分层](system.pool_tiers.md)）。
- **新计划**：有 Agent 结果的单元 Agent 行在前，规则计划作为"规则基线"在后；每条都带"证据：未验证"。
- **计划更新**：只推作废和产生新版的修订；维持、修订失败、跳过、出错都不推；扩展池入场期的链不推，持仓期的链总是推。
- **规则**：手动运行不推送；同一交易日已成功推送就不重复；休市日只发一行"纽约休市，未运行"；没有新计划也推送。
- **复盘卡行**：「复盘卡 上次推送后新增 a · 待审定 b」。复盘卡现在在推送之后才建，所以 a 是上一次每日推送之后新建的卡数，b 是推送时的待审定数；a、b 都为 0 时不出这一行。
- **数据降级行**：有数据族部分成功或失败时加一行「数据：日线 118/131（13 个目标没拿到，见运行详情）」，多个族用「；」连接，至多三个。
- **失败**：只写进运行报告，下一次推送附"上次推送失败"。字段与单条消息有长度上限，超出的整字段丢弃并注明"其余 n 条见系统"。
- **工作流失败通知**：整条链停在某个节点时另发一条「每日工作流失败」（失败节点、原因、未执行的节点数、续跑截止时间，配置了公开地址时附详情链接），每次执行至多一条；降级不发。
- 周度和月度复盘由 `retro` 节点到期时生成并推送（北京时间周二至周六 11:30 检查一次，推送类别仍是复盘）。

## 在系统里哪里看到
Discord 的 signals 频道；「今日」的"重新推送今日计划"；运行一览里 `push` 阶段的产出计数（实际发送的消息数）。

## 注意
推送是便利，不是依据：它与页面是同一份数据的摘要，价位和判断仍然未经验证。
