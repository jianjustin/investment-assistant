## 是什么
概念卡是你现在正在读的这种东西：一张卡解释一个概念（数据族、指标、规则、计划字段、Agent 字段、复盘指标、系统运作），有固定格式、版本和互相链接。它们和代码一起放在仓库里，随代码版本走，而不是写在某个会过时的文档里。

## 怎么算 / 从哪来
- **引用形式**：`concept:<id>@<版本>`，例如某张卡的第 1 版；省略 `@` 表示当前版。请求的版本不是当前版时返回当前版，并说明"该引用指向第 n 版，当前为第 m 版"；系统不保存旧版正文。
- **版本规则**：定义或口径变了才把卡的版本加 1，改措辞、补例子不加。
- **加载**：首次使用时整目录加载并校验，结果在进程里缓存到重启；改了卡需要重启服务才生效。卡有问题时，知识页面显示加载失败的问题清单，批处理和其他页面不受影响。
- **只能互链**：卡内只允许指向其它概念卡的链接，不放外链、图片，也不把你引回仓库文档。
- **不含行情**：卡里只有定义，没有具体价格、标的或日期数据。
- **Agent 读卡**：Agent 可以用 `get_concept` 读取概念卡。它是**截止时间的明示例外**：任何时候读到的都是当前代码版本的卡，结果带 `point_in_time: false`、`concept_ref` 和 `content_sha256`，原样记入工具调用记录，推理阅读视图标出"概念卡随代码版本走，不受截止时间约束"。这个例外不改提示词和 Agent 版本号，调用照常计入轮数与 token，调用编号也可被引用，但它不是价格类工具（见[工具调用](agent.tool_calls.md)）。

## 在系统里哪里看到
「知识」菜单的"概念"（浏览与互链）和"原理"；「数据」菜单、推导视图、「标的」页和计划卡上的概念名点一下就地展开摘要，再一跳到完整卡。

## 注意
卡和代码同提交更新，并有守护测试检查关键内容是否一致；但卡是人写的解释，如果你发现它与页面上的实际数字不符，请以页面和记录为准并告诉维护者。
