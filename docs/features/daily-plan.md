# 每日计划：规则 → 交易计划 → 推送

每天早上收到一份交易计划：价位能追溯到规则和数据，由你决定采纳还是否决、自己下单并录入成交。系统只给研究候选，不自动下单、不接券商；所有规则都**未经验证**（Phase 0 Gate HOLD），推送里会如实标注。

设计：[工作台](../specs/2026-10-23-us-research-workbench-design.md)、[P1 规则计划与推送](../specs/2026-10-23-p1-rule-plans-and-push-design.md)。

## 每日流程

| 时间（北京） | 发生什么 | 你要做的 |
|---|---|---|
| 周二至周六 06:30 | 任务 `workbench`：采集日线、资讯、财报日、SEC 列表、行业 ETF、FRED；跑纳指 100 筛选（成员自动进扩展池，见[观察池](pool-and-context.md)）；记录各数据族拉取结果；生成市场环境；对最近收盘交易日跑规则；生成规则计划；跑 Agent 轨道；推送。纽约休市日跳过，推一行「纽约休市，未运行」 | 无 |
| 早上 | 打开「今日」：每只股票每天一个决策单元，显示候选规则、输入值、计划价位、Agent 建议、解读（支持 / 反证 / 冲突，带引用）、近期财报与资讯；筛选来源的单元带「筛选」标记 | 采纳 / 否决 / 降级为观察，写一句理由；采纳时选执行依据：规则计划、Agent 建议或自定价位 |
| 成交后 | 「复盘 → 交易与持仓」录入成交（本机时区），关联当时的决定 | 录错就「作废」并写理由，再重新录入 |

「今日」右上可「立即运行批处理」：手动运行总是针对最近一个已收盘的交易日（纽约 17:00 后算当天收盘），**不推送**。

## 规则 v1

阈值事先固定，不用历史数据调参；改阈值就发新版本，旧信号保留原版本和输入。

| 规则 | 动作 | 条件 |
|---|---|---|
| 趋势回踩修复 `trend_reclaim` | 买入 | 收盘 > MA50 > MA200，且收盘重新站上 MA20，此前至少连续 3 天在 MA20 下方 |
| 放量突破 `volume_breakout` | 买入 | 收盘创前 20 日收盘新高，成交量 ≥ 前 50 日均量 × 1.5，收盘 > MA50 |
| 财报跳空向上 `earnings_gap_up` | 买入 | 8-K Item 2.02 后第一个交易日，开盘较前收盘跳空 ≥ +3%，收盘 ≥ 开盘 |
| 跌破 MA50 `trend_break` | 卖出 | 此前至少连续 10 天收在 MA50 上方，当日跌破 |
| 财报跳空向下 `earnings_gap_down` | 卖出 | 财报后第一个交易日跳空 ≤ −3%，收盘 ≤ 开盘 |
| 持仓回撤 `position_drawdown` | 卖出 | 仅限没有计划的持仓：收盘较成本跌 ≥ 8%，或较持仓以来最高收盘回撤 ≥ 12% |
| 新财报 `new_filing` | 观察 | 当日出现新的 10-Q / 10-K / 8-K |
| 异常波动 `abnormal_move` | 观察 | 日收益绝对值 ≥ 近 20 日波动率 × 2.5，且当日无新财报 |

- 财报时点按 SEC 受理时间（UTC）判断：盘后发布算下一个交易日，盘前算当天，盘中发布不触发跳空规则。批处理用 SEC 列表补全缺失的受理时间和 Item，只补空值、不覆盖；仍缺受理时间的财报只能触发「新财报」。
- 不足 200 根日线、当日缺日线或复权因子异常时，价格规则不产出候选，并在运行报告记录跳过原因，不写成「无信号」。
- 同一天同时出现买入和卖出候选，标记「冲突」，默认观察；没有持仓的卖出候选标记「回避」。

## 交易计划 `plan-1`

为「建议买入、无冲突、未决定」的单元生成：

| 字段 | 规则 |
| --- | --- |
| 参考价 | T 日收盘 |
| ATR | ATR14（Wilder，拆股调整口径） |
| 入场区间 | 参考价 ± 0.5 ATR |
| 止损 | 参考价 − 2 ATR |
| 目标 T1 | 参考价 + 4 ATR（2R） |
| 有效期 | T+1 至 T+3 个交易日 |
| 建议仓位 | min(资金 × `risk_pct` ÷ 每股风险，单票上限，总持仓剩余空间)；缺资金快照时只给每股风险并标 `no_equity`；没有空间就作废（`no_room`） |
| 财报 | 有效期内有财报则计划作废；之后 10 个交易日内有财报，或日期未知、已过，则加提示 |
| 市场环境 | 冻结进 `inputs.context`；防守区制、快照失败、行业弱势只加提示，不改价位 |

价位四舍五入到 0.01。重跑结果相同就返回原计划；结果不同则记入运行报告的冲突列表，不覆盖原计划。采纳时提交自定价位，会另存一份 `own` 计划，和决定在同一事务里写入，建议股数按新价位重算。

## 持仓止损

持仓的计划取「当前未平仓批次中最近一笔、且其决定关联了计划的买入」。有计划的持仓用 `plan_stop`（T 日最低价 ≤ 当前止损）和 `plan_target`（开仓以来首次触及 T1，卖出一半，只触发一次）；触及 T1 之后，当前止损 = max(开仓以来最高收盘 − 3 ATR, 持仓成本)，收盘后更新、次日生效。没有计划的持仓仍按 `position_drawdown` 判断。

## 推送

定时运行在批处理之后，把当日简报推到 Discord（默认 `signals` 频道），共五条消息：概览（含市场环境、扩展池新计划数）、新计划（核心池 + 持仓与可决定的筛选单元，规则计划与 Agent 行并列；筛选来源的计划字段名带「【筛选】」前缀）、持仓、待处理与异常、筛选报告（概览 / 今日触发 → 复核 / 形态候选前 10 只，形态列全要看页面；筛选未运行时写原因与沿用成员数）。没有新计划也推送；同一交易日已成功推送就不再重复；推送失败只写进运行报告，下次推送附「上次推送失败」。单个字段截断到 1024 字符，单条消息不超过 6000 字符。

## 入口与验证

- 页面：「今日」（决策单元、计划卡片、Agent 建议、持仓止损、市场环境、「重新推送今日计划」）；「标的」（单只股票的 K 线图（MA20/50/200 与成交量，最多 250 根日线）、日线、候选、计划与决定历史）。
- API：`GET /api/workbench/today`、`POST /api/workbench/decisions`（`plan_id` 与 `own_plan` 二选一）、`GET /api/workbench/instruments/{ticker}`、`GET/POST /api/workbench/trades`、`POST /api/workbench/trades/{id}/void`、`POST /api/workbench/push`。
- 运行报告：`job_reports` 中 `workbench` 的 `summary`，包括 `tickers.<T>`（日线、资讯、候选、跳过原因）、`plans`（`inserted` / `existing` / `conflict` / `skip: 原因`）、`earnings`、`push`、`sources`（按数据源列出失败）、`timings`。
- 验证一次：手动运行批处理后，运行报告里 `plans.<T> == "inserted"`；「今日」显示「入场区间 x–y · 止损 z · T1 w · 建议 N 股」和「证据：未验证」；点「重新推送今日计划」，页面提示「已推送 N 条」，`push.sent == true`。

## 数据与时点

- 日线保存 yfinance `auto_adjust=False` 的开高低收（已按拆股调整、未按分红调整）和全复权收盘价；数据源改了数值就追加一个修订版本，不覆盖旧值。
- 规则、计划和解读只用运行截止时间之前已入库的数据；资讯发布时间未知时显示「发布时间未知」，不用获取时间代替。
- 资讯只存标题和链接，不抓正文。
- 这不是严格的历史时点回测：yfinance 的历史数据会被修订，只能保证「本系统开始采集之后」的记录能按时点还原。

## 已知限制

- 免费资讯源不稳定：`Ticker.get_news` 已被 Yahoo 改成 404，现在改用搜索接口；运行报告里 `news.fetched` 为 0 时，说明它又失效了。
- 样本小、信号重叠多，统计没有推断意义。
- 价位是你所设规则的算术结果，不是投资建议。
