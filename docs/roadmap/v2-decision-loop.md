# Roadmap v2 — 数据 → 交易计划 → 复盘

> 状态：已完成，发布于 v2.0.0。

> 2026-10-23，基线 `main@0b7c078`。本文是与你逐项讨论后确认的长期路线（决策记录见 §9）。
> 这是方向和排序，不是实施授权。每个阶段开工前另写 spec 和 plan，按 [交付标准（DoD）](README.md#交付标准dod) 交付。
> 本文改了一条 v1 边界：[工作台形态](../archive/roadmap-v1/workbench-shape-2026-10-17.md)原写「目标价、仓位不在这套系统里完成」，现改为**系统按规则算出计划价位和建议仓位，人决定是否下单**。仍不接券商、不自动下单。

## 1. 目标与成功标准

**长期目标**：投研工作台指导投资决策。每天早上在 Discord 收到交易计划，价位可追溯到规则和数据；你自己下单并录入成交；系统按计划和结果复盘。

**优先级**：收益 > 纪律 > 认知（哪些信号和数据有用）> 省时间。

**主指标：月度账户收益率**

| 档位 | 月度收益率 |
|---|---|
| 非常优秀 | > 20% |
| 优秀 | 10% – 20% |
| 可行 | 0% – 10% |
| 需关注 | < 0% |

- 口径：（月末净值 − 月初净值 − 当月净入金）÷ 月初净值；持仓按月末收盘价计入。同一行显示同月 SPY 收益。
- **流程复查触发**：滚动 3 个月收益 < 0 **且**同期跑输 SPY。单月为负不触发。
- 阈值先按上表，用几个月后可在配置中调整。
- 预期：一年约几十笔交易，第一年做到「收益口径算得准、算得诚实」，不以「已证明跑赢」为验收。纪律指标是收益的领先指标。

## 2. 边界

- 不接券商、不自动下单、不做盘中自动交易。
- 主计划价位由版本化规则计算，可重算。Agent 给出并列建议，不改主计划。
- 每份计划标注规则的证据状态。当前所有规则都未经验证（Phase 0 Gate HOLD），推送里明说。
- 证据不够时停住：数据缺失、计划超限、Agent 引用无效，都显式标出，不写成「无信号」。
- 系统输出的价位和仓位是你规则的算术结果，不是投资建议。

## 3. 整体流程

```
① 数据进来 ──► ② 产生决策 ─────────────────► ③ 投递 ──► ④ 你确认与执行 ──► ⑤ 复盘
观察池≤100只    规则 → 主计划（价位+仓位）      06:30        系统内采纳/否决      每周 / 每月
日线/财报/      Agent → 并列建议 + 理由 + 反方   Discord      券商手动下单         Discord 摘要
资讯/ATR/       两条轨道各自影子跟踪            核心池+持仓   录入成交、关联计划
广度/利差
```

## 4. 各环节设计

### 4.1 数据

| 数据 | 用途 | 阶段 |
|---|---|---|
| 日线（已有，扩到观察池全体 + SPY + 行业 ETF） | 规则、指标、影子跟踪 | 已有 / P2 |
| SEC 财报含受理时间、资讯标题（已有） | 财报规则、解读引用 | 已有 |
| ATR（由日线算） | 止损宽度、仓位 | P1 |
| 下次财报日期 | 跨财报风险提示、计划有效期 | P1 |
| 行业 ETF 相对强度（SMH、XLK、QQQ 对 SPY） | 行业背景 | P2 |
| 池内广度（站上 MA50/MA200 占比、新高新低） | 区制标签 | P2 |
| HY 信用利差、2s10s（FRED） | 风险偏好背景 | P2 |

暂缓：期权隐含波动、分析师预期修正与 EPS 超预期（成本高或免费源不稳定）。不做：CPI、就业等宏观，社媒情绪。

**观察池**：上限 100 只，分两层。

| 层 | 规模 | 规则与 Agent | 推送 |
|---|---|---|---|
| 核心池 | 10–15 只，你挑选 | 运行 | 全部推送 |
| 扩展池 | 其余 | 运行，全部影子跟踪 | 不推送，进周度复盘 |
| 持仓股 | 不论在哪层 | 运行 | 一律推送 |

### 4.2 决策：交易计划

**规则主计划**：每个候选生成一份计划，字段如下。具体公式在 P1 spec 中定稿，改公式即发新版本。

| 字段 | 内容 |
|---|---|
| 依据 | 触发规则与版本、输入快照 |
| 入场方式与区间 | 回踩类用限价区间，突破类用触发价；高于上限视为追高 |
| 止损（失效价） | 结构位与 ATR 倍数结合 |
| 目标 | T1 按 R 倍数；T2 用移动止损 |
| 建议仓位 | 总资金 × 单笔风险 ÷（入场 − 止损），再受上限约束 |
| 有效期与失效条件 | 到期作废；有效期内遇财报等事件提前作废 |
| 风险提示 | 下次财报日、行业强弱、区制 |
| 证据状态 | 规则是否经过验证（当前均为未验证） |

**仓位默认值**（工程参数，后续凭数据调整）：

| 参数 | 默认值 |
|---|---|
| 单笔风险 | 总资金 1% |
| 单票上限 | 总资金 25% |
| 总持仓上限 | 100%，不加杠杆 |

超限计划照常显示，标为「不合格」并写原因，不作为可执行计划推送。

**Agent 并列建议**：Agent 用工具获取原始数据和指标，推演后独立给出入场、止损、目标和理由。

- 每个价位必须追溯到工具调用结果；引用不存在的数据整条作废。
- 只能读运行截止时间之前的数据。
- 通过基本校验（如买入止损低于入场）。
- 「反方」步骤：专门找反证、核对引用和数字，写进风险提示，不改价位和动作。

**你的确认**：在系统内采纳或否决，并记录照哪条执行：规则、Agent，或你自改的价位。

### 4.3 投递

| 时间（北京） | 内容 | 渠道 |
|---|---|---|
| 每天 06:30 批处理后 | 核心池与持仓的计划（规则主计划 + Agent 建议）、持仓止损更新、待决定单元、运行异常 | Discord |
| 每周 | 周度复盘摘要 + 系统链接 | Discord |
| 每月 | 月度复盘摘要 + 系统链接 | Discord |

邮件暂不接入工作台推送。采纳和否决只在系统内操作。

### 4.4 复盘

**影子跟踪**：规则计划和 Agent 建议各自按自己的价位假设执行，逐日判断止损或目标先到、是否到期，结果以 R 计，同时保留 5/10/20 日相对 SPY 的超额收益。影子结果不受你实际选择影响。

**每周复盘**

| 视角 | 内容 |
|---|---|
| 规则 | 每条规则的触发次数与影子结果 |
| 轨道对比 | 规则、Agent、你实际执行，三方结果并列 |
| 纪律 | 追高进场、过早止盈、死扛亏损、计划外交易 |
| 分池 | 核心池与扩展池分开 |

纪律指标口径：

| 坏习惯 | 判定 |
|---|---|
| 追高进场 | 成交价高于计划入场区间上限 |
| 过早止盈 | 未到 T1 卖出，之后价格到达 T1 |
| 死扛亏损 | 收盘跌破止损后，下一交易日未卖出 |
| 计划外交易 | 成交未关联任何计划 |

**每月复盘**：月度收益率与分档、同月 SPY、滚动 3 个月复查标记、单笔风险敏感性表（用当月真实 R 结果按 0.5% / 1% / 1.5% / 2% 重算收益和回撤）。需要你录入月末总资金和当月出入金。

样本小且同日重叠，复盘只给计数、均值、中位数和分布，不宣称规则或 Agent 有效。

### 4.5 回测的位置

| 方式 | 用途 | 限制 |
|---|---|---|
| 前向影子跟踪（主力） | 规则与 Agent 的主要证据来源，无前视偏差 | 慢 |
| 观察池历史事件研究（辅助） | 新规则上线前检查：触发是否过频、止损是否总被扫掉；指标预热区与评估区分开 | 不调参数，不宣称有效 |

不做全组合净值回测，不回溯 S&P 500 等大池子。

### 4.6 Agent 运行时

| 项 | 决定 |
|---|---|
| 运行时 | LangGraph，用其自带的工具调用循环；状态存现有 PostgreSQL（PostgresSaver） |
| 模型 | 默认智谱（OpenAI 兼容接口）；模型与接入方配置化，便于以后加入其他模型对比 |
| 工具层 | 普通 Python 函数，独立模块；LangGraph 只做薄包装，需要时可暴露成 MCP |
| 截止时间 | 由批处理传入工具层，模型不能决定或修改 |
| 调用记录 | 每次工具调用的参数、返回值、哈希写库，供引用校验 |
| 费用 | 每日 token 预算；超限停 Agent 轨道并写入运行报告，规则轨道不受影响 |
| 现有 Codex 解读 | 暂时保留；Agent 轨道稳定后合并为一条 |

未选：Pi Durable（TypeScript 实验包、无测试，强项是多人协作与会话分叉，不是本项目需求）；Codex CLI + MCP 过渡方案（换模型不便，后续要重做）。

### 4.7 进化

- **形态**：冠军 / 挑战者。规则主计划是冠军；Agent 和以后其他版本是挑战者，只影子跟踪、并列展示。
- **当前只观察**：不设晋升标准，不安排替换主计划。
- **版本照记**：规则、计划参数、提示词、模型都带版本，保证以后能分清历史结果由谁产出。
- **不做**：多 workflow 投票合成；让辩论结果决定动作。对抗只以「反方」步骤的形式存在。

## 5. 阶段

日期为预估顺序，不是承诺。每阶段满足退出条件后再进下一阶段。现有四周使用观察（10-23 开始）与开发并行。

| 阶段 | 预估时间 | 内容 | 退出条件 |
|---|---|---|---|
| **P1 规则计划与推送** | 2026-10 下旬 – 11 月底 | ATR；下次财报日期；账户参数与月末资金、出入金录入；交易计划表（只追加、带版本）与校验；计划影子跟踪（止损/目标/到期，以 R 计）；06:30 Discord 推送；成交关联计划与执行轨道选择；四个纪律指标；月度收益率与分档 | 连续两周每天按时收到计划；每份计划可从输入重算；每笔成交关联到计划或标为计划外；11 月月度收益算出 |
| **P2 观察池扩展与市场环境** | 2026-12 | 观察池上限 100 并分层；行业 ETF 相对强度；池内广度与区制标签；FRED HY 与 2s10s；观察池历史事件研究（上线前检查） | 批处理在 100 只规模下按时完成；每份计划显示区制与下次财报日；各数据源失败可在运行报告中区分 |
| **P3 Agent 轨道** | 2027-01 – 02 月中 | 工具层；LangGraph + 智谱；反方步骤；引用校验；token 预算；Agent 影子跟踪；推送中并列展示 | 连续两周每个候选都有 Agent 建议或明确失败原因；无效引用被拦截；预算超限时规则轨道照常推送 |
| **P4 复盘扩展** | 2027-02 – 03 | 三方轨道对比；滚动 3 个月复查；敏感性表；周度与月度 Discord 摘要；Codex 解读并入 Agent 轨道 | 完成一次完整月度复盘并推送；三方对比可追溯到每份计划 |

跨阶段始终成立：只追加写入、按时点可还原、离线测试（外部依赖 mock）、手动入口 + 验证入口、不自动下单。
