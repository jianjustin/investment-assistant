## 1. 目标与成功标准

**目标**：主线「自动化扫描纳指100 / 手动研究寻找波段投资标的 → 生成投资计划 → 复盘」不变，这段演进把每个环节变得**看得见、看得懂**——数据从哪来、每类数据为什么存在、信号从哪些数据变化中来、计划怎么一步步算出来、当天整体运行走了哪些节点。

**优先顺序**：先数据底座（用户可能人工看数据），后计划推导，再运行全景与页面重排。

**成功标准**（对应用户三痛点）：

| # | 标准 |
|---|---|
| 1 | 「数据」菜单能回答每类数据的用途、覆盖、新鲜度，支持手动拉取，并能浏览原始数据值 |
| 2 | 任何一份计划都能展开「从原始输入到每个价位的推导链」，不读代码即可复核 |
| 3 | 任何一天都能看到运行全景：批处理各阶段的处理量、产出、跳过与原因 |
| 4 | 「标的」页首屏按投资流程组织：先信号与计划，后背景数据 |

## 3. 设计要点

### 3.1 数据底座与「数据」菜单（v2.3）

- **数据族**：日线、SEC 财报、资讯、ATR、FRED 利差（HY/2s10s）、纳指100 范围。
- **数据族状态层（底座本体）**：数据族清单 + 状态记录——每族覆盖哪些标的、最新数据到什么时点、最近拉取成败与原因、所属调度任务。工程上是一张只追加的状态记录表加读取接口。
- **操作**：单族手动拉取（复用现有采集入口，走同一写入路径）；调度开关沿用任务中心。
- **「数据」菜单前端**：①状态总览（每族一张卡：用途、覆盖数、最新时点、最近成败）②原始数据浏览（如某只票的日线、某条 FRED 序列的实际值）。
- **人工看数据的程度**：状态总览 + 浏览原始值；导出（CSV 等）与日期范围筛选暂不做，需要时再加。
- **本轮不新增数据族**：主线（波段筛选→计划→复盘）所需数据已齐，缺的是可见性；期权 IV、EPS 超预期无稳定免费源，维持暂缓。

### 3.2 批处理 workflow 化（v2.4 工程底座）

- **阶段划分**：数据采集（范围/日线/财报/资讯/FRED）→ 筛选 `screen-1` → 信号与候选 → 规则计划 `plan-1` → Agent 建议 → 复核与推送。
- **证据记录**：每阶段只追加写入 `stage_runs` 类记录——输入计数、输出计数、跳过及原因、失败与降级、耗时、产出引用。
- 现有 `run_log`、运行报告保留；全景视图与推导视图共用同一套记录，不做两套。
- 每版 spec 定稿阶段定义（stage id、字段 schema）。

### 3.3 单份计划推导视图（v2.4 主交付）

- 每份计划 / 决策单元可展开推导链：**触发规则与版本 → 当时输入快照（价格、ATR、区制、筛选分组…）→ 逐项计算（入场区间 / 止损 / 目标 / 仓位：公式 + 代入值）→ 校验结果**。
- 数据来源：计划已有的「依据 + 输入快照」；推导视图是展示层，不改变计算逻辑。
- 任何价位可由推导链重算（沿用「每份计划可从输入重算」原则）。

### 3.4 当日运行全景（v2.5）

- workflow 节点图：节点=阶段、边=数据流；点开节点看该阶段当日证据记录。
- 回放历史某一天（读取 `stage_runs`，只读）。

### 3.5 「标的」页重排（v2.5）

- 结构：①信号与计划（今日触发、有效计划、持仓）→ ②关键数据（推导链所需输入）→ ③背景（基本面、下次财报日、行业强弱、区制）→ ④历史（K 线与标注）。
- 与 §3.3 推导链互相链接；页面元素不新增数据，只重排与收敛。
- backlog 的「K 线图标注候选与计划价位」并入本版。

## 4. 边界

- 沿用：不接券商、不自动下单、不做盘中自动交易；只追加写入、按时点可还原；价位是规则算术结果并标注证据状态（Phase 0 Gate HOLD 照旧）；每版 spec→plan→DoD；真实库迁移先 `pg_dump` 备份并单独授权；push 单独授权。
- 新增：工作台与 #投研-工作（Team B）是两个独立系统，不做衔接；「手动研究」仅体现为用户手动维护核心池/观察名单。
- 证据与验证不做专项，随主线复盘自然积累；验证判据等有几个月数据再议。
