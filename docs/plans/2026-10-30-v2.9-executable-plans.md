# v2.9.0 可执行的计划 Implementation Plan

> **For agentic workers:** 按 Task 顺序执行；每个 Task 的步骤用 checkbox（`- [ ]`）跟踪。实现子代理用别名 `sonnet`，审查用 `opus`（项目 `CLAUDE.md`）。**本 plan 待用户确认 spec 与本文后才开始执行**；spec §19 的待确认项若被推翻，先改 spec 对应章节（以追加「确认结果」一节的方式），再按改后的 spec 执行。

**Goal:** 一只股票同一时间至多一条活跃链（`timeline-2`）：再次触发由 `plan` 节点写 `chain_retriggers`、`agent` 节点不再开新链、`review` 节点以 `retrigger` 信号进已有链复查（入场期直接修订，价位不变可「续期」），首版提议带「同标的上一条链」证据块；计划写成执行指令（`entry-1` 三种入场类型、开盘三种情形、何时作废，规则基线 `plan-2`、Agent `agent-3`，影子 `plan-shadow-2` 与 `plan-shadow-1` 并列）；取消决定按钮，成交关联计划版本（`trades.plan_id`），采纳由成交推导（`execution-1`），三方对比、纪律、复盘卡、周 / 月复盘改版（`tracks-2`、`discipline-2`、`retro-2`、`review-8`、`monthly-4`）；时间止损（`condition-2` 的 `held_sessions_reached`）、持仓期作废进入退出期、每个持仓每日一行 `holding_status`；「今日」计划表（三组、已结束置灰收起）、「标的」页计划历史、推送改版。迁移 029。

**Architecture:** 纯函数层新增 `workbench/entry_rules.py`（`entry-1`：开盘情形、作废清单、入场模拟）与 `workbench/execution.py`（`execution-1`：成交 → 计划 → 链、执行状态），扩展 `timeline.py`（`timeline-2` 状态、`retrigger` 信号、入场期上限、上一条链证据块、持仓状态）、`agent/conditions.py`（`condition-2`）、`plans.py`（`plan-2`）、`plan_shadow.py`（`plan-shadow-2`）、`agent/plan_check.py`（`agent-3`）、`discipline.py`、`tracks.py`、`retro.py`；编排层改 `service.py` 的 `plan` / `agent` 阶段函数与 `plan_review.py` 的复查流程（`daily` 图本身不变，`stages-4` 十个节点不变）；读视图新建 `workbench/plan_views.py`（计划表、计划历史、持仓状态视图、可关联计划）经 `api/routes/workbench.py` 暴露；前端新组件 `PlanTable.svelte`、`PlanHistoryTable.svelte`，改「今日」「标的」「计划」「复盘」四页。

**Tech Stack:** Python 3.11 / FastAPI / psycopg 3 / PostgreSQL；LangGraph（`daily` 图不改）；Svelte 5 + Vitest；pytest（离线，SQL 测试用一次性库）。无新依赖。

**Spec:** [docs/specs/2026-10-30-v2.9-executable-plans-design.md](../specs/2026-10-30-v2.9-executable-plans-design.md)

## Review Focus

1. **截止时间泄漏**：上一条链证据块用了截止时间之后的复查 / 成交 / 日线；`get_position` 仍读到截止之后录入的成交；`retrigger` 证据块带了截止之后的候选。→ Task 2 `test_previous_chain_block_respects_cutoff`；Task 3 `test_get_position_respects_cutoff`、`test_retrigger_evidence_respects_cutoff`、`test_first_version_prompt_has_previous_chain_block`。
2. **唯一活跃链被破坏**：`plan` 与 `agent` 节点之间、手动「重新运行 Agent」、同 session 重跑时为同一标的开出第二条链。→ Task 3 `test_plan_node_writes_retrigger_for_active_chain`、`test_agent_node_rechecks_active_chain_under_lock`、`test_manual_rerun_rejects_active_chain`、`test_rerun_session_idempotent_retriggers`、`test_check_flags_two_active_chains`。
3. **旧数据语义被改写**：旧决定不再让链终止、旧 `retro-1` 卡或旧快照被重算、旧 `plan-1` 行被重算或补字段、出现对旧行的 `UPDATE`。→ Task 2 `test_closed_by_decision_still_terminal_for_legacy`、`test_invalidate_rows_timeline1_keep_terminal`；Task 4 `test_retro1_cards_render_unchanged`、`test_old_snapshots_not_recomputed`；Task 6 `test_no_update_on_append_only_tables`（静态扫描 SQL）。
4. **影子与开盘文案不一致**：页面写「作废」而影子成交、`next_open` 看了第二天、时间止损按当天收盘退出。→ Task 2 `test_shadow_v2_matches_scenarios`（参数化三类型 × 三情形）、`test_time_stop_exits_next_open`、`test_next_open_only_first_session`。
5. **持仓状态缺行**：复查跳过 / 出错 / Agent 不可用 / 无链持仓 / 退出期的标的当天没有 `holding_status`。→ Task 3 `test_holding_status_written_when_review_skipped`、`..._when_review_errors`、`..._for_positions_without_chain`、`..._for_exiting_chain`、`test_check_flags_missing_holding_status`。
6. **决定残留**：生产代码仍写 `signal_decisions`、前端仍有决定表单、推送仍有「未决定单元」、新成交仍能带 `decision_id`。→ Task 4 `test_decisions_post_410`、`test_trades_reject_decision_id`、`test_no_insert_decision_outside_tests`；Task 3 `test_digest_has_no_undecided_units`；Task 5 `Today.test.ts › no decision form`。
