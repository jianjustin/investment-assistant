# v2.5.0 计划时间线 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Agent 计划结构化为 `agent-2`（论点、关键反证、失效条件、下次复查条件、相对上版变化）并成为「今日」与推送的默认复查对象；同一单元的 Agent 计划有只追加的版本链，批处理第 8 个阶段 `review` 每日复查，系统信号与用户输入触发修订；每版独立影子跟踪，三方对比取你决定时看到的那一版。

**Architecture:** 纯函数三件套：`agent/conditions.py`（条件集合 `condition-1`）、`agent/plan_check.py`（`agent-2` 输出与复查输出校验，在 `citations.check_proposal` 之后追加）、`workbench/timeline.py`（链状态 `timeline-1`、版本计划行、宿主差异、六项信号、宿主结论）。`agent/graph.py` 新增 `agent-2` 提议 / 反方 / 修订与单阶段复查图，工具层不变。`workbench/plan_review.py` 是复查阶段编排、重新复查、链视图与 CLI；`workbench/user_inputs.py` 是用户输入用例。每一版是一行 `trade_plans`，链关系在迁移 026 的 `agent_plan_versions`，复查记录在 `plan_reviews`，用户输入在 `user_inputs`。前端新增 `AgentPlanCard` / `RuleBaseline` / `PlanTimeline` / `UserInputs` 组件，挂在「今日」、计划页与「标的」页。

**Tech Stack:** Python 3.11 / FastAPI / psycopg 3 / PostgreSQL；LangGraph + 智谱（不变）；Svelte 5 + Vitest；pytest（离线，SQL 测试用一次性库）。

**Spec:** [docs/specs/2026-10-28-v2.5-plan-timeline-design.md](../specs/2026-10-28-v2.5-plan-timeline-design.md)

## Review Focus

1. **信号日当次批处理**：`agent` 阶段刚生成首版，同一次运行的 `review` 阶段不能再复查它（`fresh_version`），`plan_review check` 也不能把它报成缺记录。→ Task 7 `test_fresh_version_not_reviewed_same_run`、Task 8 `test_check_accepts_fresh_version`。
2. **同一事件天天触发**：D 日 T1 触及、复查维持，D+1 不能再触发 `t1_touched`（窗口是「上次复查之后」）。→ Task 4 `test_signals_window_since_last_review`。
3. **决定时页面停留在旧版**：用户看着第 1 版，批处理已出第 2 版，提交决定必须 409 且不写决定。→ Task 9 `test_decision_with_stale_agent_plan_is_409`。
4. **持仓期修订因仓位规则作废**：敞口含已持有的这只股票，新版 `no_room` → `status = invalid`，链仍是 `holding`、次日照常复查。→ Task 4 `test_holding_revision_no_room_keeps_chain_active`、Task 7 `test_holding_chain_reviewed_after_invalid_version`。
5. **重新复查与批处理撞上同一条链**：锁被占时批处理跳过（`review_in_progress`，不写行），重新复查返回 409。→ Task 8 `test_recheck_and_batch_are_mutually_exclusive`。
