# v2.8.0 每日工作流 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 三个定时任务（`filings`、`workbench`、`workbench_review`）合成一张 LangGraph 图 `daily`（北京 11:30 周二至周六，十个节点 `stages-4`），PostgresSaver 检查点 + 节点级自动重试一次 + 详情页「从此节点继续」；外部请求统一紧超时与按目标有限重试（`fetch-1`），逐目标明细进 `data_fetch_runs.detail.targets`；运行详情页；Agent 模型层改走 Sign in with ChatGPT（OAuth 动态注册、刷新、Responses API），删除智谱。迁移 028 改 `stage_runs`（`attempt`、`daily`、`sec_monitor`）、新建三张表、调度三行合一。

**Architecture:** 基础层 `data/fetch_policy.py`（策略、会话、硬截止）套到 Yahoo / SEC / FRED / Discord 的每个调用点，`collect.Tally` 记目标级明细；`service.run_batch` 按阶段边界拆成九个阶段函数，`workbench/workflow.py` 用 `StateGraph` 把十个节点首尾相连，`node()` 包装负责证据行、计时与 60 秒重试，`tasks/daily.py` 是唯一的任务外壳（锁、`job_reports`、失败通知、续跑）；模型层 `agent/chatgpt.py`（OAuth、令牌、请求改写）+ `workbench/agent_connection.py`（连接用例）+ `agent/model.py`（`SiwcChatOpenAI` 或 `ResponsesChatModel`）；只读用例 `workbench/run_detail.py` 经 `api/routes/runs.py` 暴露；前端新增运行详情页与「设置 → Agent 连接」。

**Tech Stack:** Python 3.11 / FastAPI / psycopg 3 / PostgreSQL；LangGraph 1.2（`StateGraph`、`PostgresSaver`）；`langchain-openai` 1.7.2 + `openai` 3.37 走 Responses API；yfinance 1.7（`curl_cffi` 会话）；Svelte 5 + Vitest；pytest（离线，SQL 测试用一次性库，外部请求用本地假服务器）。无新依赖。

**Spec:** [docs/specs/2026-10-29-v2.8-daily-workflow-design.md](../specs/2026-10-29-v2.8-daily-workflow-design.md)

## Review Focus

1. **续跑读到截止时间之后的数据**：续跑换了截止时间、采集节点写入来源时间晚于 `cutoff_at` 的资讯 / 申报、过了下一交易日纽约 17:00 仍放行。→ Task 2 `test_resume_reuses_cutoff_and_session`、`test_resume_collect_drops_items_after_cutoff`、`test_resume_rejected_after_next_session_close`。
2. **重试把 Agent 预算吃光**：`agent` / `review` 仍按运行开始计时，采集节点的重试与节点级 60 秒等待挤掉 Agent；`retro` 挪到推送后被共用窗口饿死。→ Task 2 `test_agent_budget_starts_at_agent_node`、`test_collect_retries_do_not_shrink_agent_budget`、`test_review_shares_agent_window`、`test_retro_has_own_window`。
3. **token 进日志或接口**：异常文本、`agent_connection_events.detail`、`last_error`、连接状态接口、运行详情、`summary` 里出现 access / refresh token 或 `Bearer …`。→ Task 3 `test_tokens_never_logged_or_returned`、`test_connection_view_has_no_token_fields`、`test_classify_error_redacts_bearer`；Task 4 `test_settings_agent_connection_api_never_returns_tokens`。
4. **`stage_runs` 行数守护**：某条路径少写 / 多写一行、续跑给已完成节点追加了行、`derivation stages` 没有按有效行判断。→ Task 2 `test_daily_ten_rows_each_path`、`test_resume_appends_attempt_rows_only_for_rerun_nodes`、`test_resume_skips_completed_nodes`、`test_derivation_stages_accepts_resumed_runs`。
5. **休市日与 `not_due`**：休市时 `sec_monitor` 或 `retro` 被一并跳过、周 / 月复盘该推没推、交易日 `retro` 误记 `not_due`。→ Task 2 `test_holiday_skips_before_push_and_retro_judges_due`、`test_retro_not_due_on_non_trading_day`、`test_retro_after_push_failure_does_not_block_push`。
6. **删智谱漏网**：代码、配置、文档、测试夹具、前端测试里残留 `zhipu` / `bigmodel` / `ZHIPU_API_KEY` / `glm-5`。→ Task 6 `test_no_zhipu_residue`（允许清单按 spec §9）。
