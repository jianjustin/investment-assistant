# v2.2.0 每日筛选与任务中心自描述 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 任务中心统一北京时间、每个任务自带说明；工作台批处理每天从纳指 100 筛出波段候选，自动进扩展池，用 `plan-1` 复核，有效计划可直接决定，并推送筛选报告。

**Architecture:** 纯函数 `workbench/universe.py`（范围文件）和 `workbench/screen.py`（`screen-1` 过滤、排序、成员轮换）不碰数据库；`workbench/screening.py` 负责采集范围日线、调用纯函数、写 `screen_runs` / `screen_results`、组装报告和只读回放；`service.run_batch` 在读出手动观察池之后、同步分层之前调用它。观察池 = 手动名单 ∪ 筛选成员（`pool_tiers.source = screen`），之后的规则、计划、Agent、推送沿用现有链路。

**Tech Stack:** Python 3 / FastAPI / psycopg 3 / PostgreSQL；Svelte 5 + Vitest；pytest（离线，数据库用一次性 schema）。

**Spec:** [docs/specs/2026-10-25-v2.2-screener-and-task-center-design.md](../specs/2026-10-25-v2.2-screener-and-task-center-design.md)

## Global Constraints

- 只在 `main` 上开发和提交（项目约定），不开分支或 worktree。
- 功能、架构、运维文档与对应代码同一个提交更新；spec 和本 plan 写成后不改正文。
- 业务数据只追加；筛选不写 `watchlist_items`，不写 `signal_candidates`（范围内的规则只用来判断触发组）。
- 版本号：`screen-1`、`regime-2`、`context-2`、`review-5`；旧记录保留原版本。
- 阈值（spec §5.3、§6）：20 日平均成交额 ≥ 50,000,000 美元；ATR14 / 收盘 ∈ [0.02, 0.06]；财报排除窗口 5 个交易日；每天新入选 ≤ 20；筛选成员 ≤ `min(40, 100 − 手动观察池数)`；保留期 10 个交易日（含当天）；范围文件 `as_of` 超过 120 天记 `universe_stale`；筛选步骤 > 600 秒记 `screen_over_budget`；回放 1 ≤ N ≤ 20，默认 5。
- 触发组规则：`trend_reclaim`、`volume_breakout`；排序键 RS = ½(r20 − r20(QQQ)) + ½(r60 − r60(QQQ))，r 用 `adj_close`。
- 推送：字段 ≤ 1024 字符、单条 ≤ 6000 字符；手动运行不推送；同一交易日推送成功不重复推；照旧标注「证据：未验证」。
- 时区：调度与显示都是 `Asia/Shanghai`，显示后缀「北京」。
- 测试命令：`env -u INVESTMENT_ASSISTANT_DATABASE_URL -u INVESTMENT_ASSISTANT_TEST_DATABASE_URL -u TEST_DATABASE_URL .venv/bin/python -m pytest tests/ -q`（离线）；SQL 测试另设 `INVESTMENT_ASSISTANT_TEST_DATABASE_URL` 指向端口 55433 的一次性库；前端 `cd web && NODE_OPTIONS=--no-experimental-webstorage npm test && npm run build`。
- 真实库执行迁移 023、打 tag、推送 `origin` 都要用户单独授权，不属于自动步骤。

**与 spec 的一处命名偏差**：spec §10 的 `screen_results.group` 是 SQL 保留字，列名改用 `screen_group`，接口字段仍叫 `group`。

## Review Focus

1. **筛选股被手动加入观察名单，之后又删掉**：`source` 依次 `screen → watchlist → screen`（仍在保留期）或 `removed`，每次只追加一行，不会每天重复写。→ Task 5 `test_tier_changes_source_flip_and_back`、Task 7 `test_manual_source_flip`。
2. **同一交易日重跑批处理（手动跑一次，定时再跑一次），或「重新推送今日计划」不带 `summary`**：`screen_runs` 追加新行、读取取最新；成员不变，`pool_tiers` 不重复写；推送的筛选报告从库里读，不依赖 `summary`。→ Task 7 `test_rerun_same_session_is_stable`、Task 8 `test_force_push_reads_screen_from_db`。
3. **手动观察池接近或达到 100 只**：上限 `100 − 手动数` ≤ 0 时筛选成员为空（锁定的除外并记 `screen_locked_over_cap`），不让 `Pool` 抛出超限错误、整个批处理失败。→ Task 4 `test_members_cap_zero_keeps_only_locked`、Task 5 `test_with_screen_never_exceeds_max_pool`。
4. **大批范围股票采集失败（yfinance 限流）**：失败的记 `sources.bars` 与跳过原因，不算 `illiquid` / `no_setup`；`regime-2` 样本只算当日有 K 线的。→ Task 7 `test_universe_fetch_failures_are_skips_not_filters`。
5. **筛选股出了计划但计划作废（财报 / `no_room`），或只有观察信号**：留在扩展池只读，不进待决定列表，不进「新计划」消息；报告里写作废原因。→ Task 7 `test_invalid_screen_plan_stays_read_only`。
